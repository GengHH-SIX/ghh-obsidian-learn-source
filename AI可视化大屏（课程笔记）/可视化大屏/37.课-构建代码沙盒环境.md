### 一.知识点
#### 1.with语法的用处

	1. with 已经被抛弃，官方不建议使用！（所有有没有其他方法实现沙盒？？？）
	
	2. with(obj)默认会依obj对象为全局对象作为运行上下文
	- 例如访问变量a（ with(obj){ console.log(a)} ）就等效于 console.log(obj.a)
	
	1. with(obj)会触发Object的in操作符。（也就是 Proxy 的 handler.has 方法可以看作是针对 `in`操作的钩子）
	
	注：这个钩子可以拦截下面这些操作：
	- 属性查询：`foo in proxy`
	- 继承属性查询：`foo in Object.create(proxy)`
	- `with` 检查`: with(proxy) { (foo); }`
	- [`Reflect.has()`](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Reflect/has)
   `

#### 2. 结合Proxy 的 handler 拦截

	   1.一般访问对象的属性(obj.a)时候，会先被get()拦截
		- 先访问的key是  Symbol.unscopables; 这个符合是可以配置对象的某些属性会不会出现在执行环境中
		- 再访问的key是 'a'
		- 也就是会触发两次 get();
		
	   2. 如果obj中没有这个key，且这个key出现在白名单中。则从全局对象中查找。如果白名单中没有，则返回的个undefined

#### 3. 所以要绑定handler中的has()
	1.由于使用了with()，以obj为队外层，（全局作用域中）使用任何变量时，都会最先被has()拦截
	2.has()返回false时，不会再被get()拦截，也就走不到get()中，此时会向外层作用域中查找，比如Window 或者 globalThis。所以会将 has()指定层默认返回true；确保访问变量时能被get()拦截到

#### 4.使用白名单
	1.只有出现在白名单中的全局变量，才能被正常使用

#### 5. 注意获取globalThis上的对象时的this指向问题
	1.比如在函数体中的使用了 setTimeout等api的时候，如果不绑定this, 运行时会出现丢失this报错的问题，所以说在使用到globalThis上的方法时，先给他绑定this为globalThis。

```javascript
const obj = {a:123,b:456}  
  
const useObj = new Set(['console'])  
const proxy = new Proxy(obj, {  
    has(_,key){  
    
        console.log('==>has',key);  
        
        return true;  
    },  
    get (target,key){  
        if(key === Symbol.unscopables ) return
          
        console.log('==>访问的kay是：',key)  
        
        if(Object.hasOwn(obj, key)){  
            return obj[key]  
        }else if(useObj.has(key)){  
        
            console.log('==>走globalThis:',key) 
             
	        const value = globalThis[key]
	        return typeof value !== 'function' ? value : value.bind(globalThis)
        }  
    }  
})  
with (proxy) {  
  console.log(a)  
}

// 控制台会输出：
//
//==>has console
//==>访问的kay是： console
//==>走globalThis: console
//==>has a
//==>访问的kay是： a
//123

//拦截顺序
// has(){return true} --> get(key=Symbol.unscopables) --> get(key=a)
```
