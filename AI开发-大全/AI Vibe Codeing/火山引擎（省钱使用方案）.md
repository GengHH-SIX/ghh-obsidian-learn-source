这几个是 Coding Plan 内的"尝鲜版"模型，model_id 带日期后缀，pricing 里按 model-id 名字查不到（它们通过 Coding Plan 配额抵扣，不单独计费）。基于已经拿到的全部信息给出结论。

### Coding Plan 选模型建议：「能力强 + 用量增长慢（配额消耗省）」的最佳平衡

你当前订阅的是 **Coding Plan 个人版 Lite**（¥38/月），按"会话 token"走套餐配额消耗，配额用完要么等重置、要么升级 Pro。**配额消耗速度 ≈ 输入/输出 token 加权成本**，所以"用量增长慢"本质上要看**模型单价（千 tokens）**——越便宜的模型在同等对话量下配额用得越慢。

#### 结论（针对你提的两个诉求）

**综合"编码最好 + 用量增长最慢"——推荐 `GLM-5.3-Flash`**
- 官方描述里唯一明确标了 **"Coding 能力开源 SOTA"**；
- 输入 ¥0.0008/千 tokens、输出 ¥0.0028/千 tokens，**是 Coding Plan 里单价最低的一档**（只比 Doubao-Seed-2.0-mini 略高，但 mini 的复杂编码能力明显弱）；
- 在你 Lite 套餐配额下，同等代码任务消耗大约是 DeepSeek-V4-Pro 的 1/10、Doubao-Seed-2.1-turbo 的 1/4，**配额用得最慢且编码能力是第一梯队**。

**分场景建议**：
- **日常写业务代码、补全、改 bug、解释代码** → `GLM-5.3-Flash`（省 + 强，主力）
- **超大型仓库/超长上下文（几十万 tokens 的工程）** → 切 `Kimi-K3` 或 `GLM-5.3`（1M 窗口，但旗舰消耗快，只在需要时开）
- **复杂系统设计/深度推理/攻坚难题** → `DeepSeek-V4-Pro 正式版` 或 `Doubao-Seed-2.1-turbo`
- **图省事不想来回切** → `auto` 模式，简单问题自动用便宜模型，疑难问题自动升旗舰，整体配额消耗比手选旗舰省不少

另外，你当前 Lite 版月度配额只用了约 3%、周 6%、会话 48%（截至 2026-09-17），余量非常充足；如果后期发现会话维度配额容易触顶，可以把主模型切到 GLM-5.3-Flash 来显著延缓消耗速度。
