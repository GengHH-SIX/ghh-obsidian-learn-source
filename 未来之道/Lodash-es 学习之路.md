## 🧱 第一阶段：类型检测与边界防错（1 ~ 6 题）

_核心目标：攻克 JS 各种奇葩的类型边界。面试官最爱在现场手写时看你对边界的处理是否优雅、严谨。_

- 1. `isObject` 与 `isObjectLike`
    
    - 面试痛点：为什么 `typeof null` 是 `'object'`？怎么一句话区分“广义对象”和“类对象”？
    - 源码精髓：看 Lodash 极其精简的单行类型过滤逻辑。
    
- 2. `isNil`
    
    - 面试痛点：如何一次性判断一个变量既不是 `null` 也是 `undefined`？
    - 源码精髓：理解 `value == null` 的隐式类型转换妙用（在 Lodash 中有大量替代常规判断的写法）。
    
- 3. `eq`
    
    - 面试痛点：`NaN === NaN` 为什么是 `false`？`-0 === +0` 在内存中真的一样吗？
    - 源码精髓：精巧融合了 `Object.is` 的思想，用四行代码搞定现代 JS 的严格相等判定。
    
- 4. `isPlainObject`
    
    - 面试痛点：怎么排除数组、`window` 对象或者用 `new MyClass()` 创建的实例，只留下最纯粹的字面量对象 `{}`？
    - 源码精髓：追溯原型链顶端，通过 `.constructor === Object` 进行终极拦截。
    
- 5. `isEmpty`
    
    - 面试痛点：怎么写一个通用的判断，让它同时支持判断字符串、数组、对象、Map、Set、甚至是类数组（Arguments）是否为空？
    - 源码精髓：涉及大量的底层判定（调用内部 `.internal/getTag`），是类型判断里的“集大成者”。
    
- 6. `isArguments` (依赖 `.internal/getTag`)
    
    - 面试痛点：怎么区分一个长得很像数组的对象，到底是真正的数组，还是函数的 `arguments` 参数？
    - 源码精髓：大厂面试常考的 `Object.prototype.toString.call(value)` 经典工程实践。

## 🧪 第二阶段：数组操作、去重与迭代变换（7 ~ 12 题）

_核心目标：手写原生数组的高级变体。大厂笔试、一轮技术面最爱考的算法基础。_

- 7. `head` (或 `first`) 与 `last`
    
    - 面试痛点：最安全的获取数组首尾元素的做法，如何防止在数组为 `null/undefined` 时报错（防崩溃）？
    - 源码精髓：极限的安全判空保护。
    
- 8. `compact`
    
    - 面试痛点：如何高效过滤掉数组中的所有“虚值”（`false`, `0`, `""`, `null`, `undefined`, `NaN`）？
    - 源码精髓：了解 Lodash 为什么不用自带的 `filter(Boolean)`，而是选择用更快的 `for...of` 和直接操作索引。
    
- 9. `uniq` (核心底层：`.internal/baseUniq`)
    
    - 面试痛点：现场手写数组去重。除了 ES6 的 `[...new Set(arr)]`，如果要兼容大数量、老版本，传统的大厂工业级去重是怎么实现的？
    - 源码精髓：看它如何针对短数组（用 `includes`）、长数组（动态创建内置 `Set`）进行性能分流优化。
    
- 10. `flatten` 与 `flattenDeep` (核心底层：`.internal/baseFlatten`)
    
    - 面试痛点：现场手写数组扁平化（降维）。如何实现任意层级的扁平化？
    - 源码精髓：利用循环+递归，配合一个控制深度的计数器，优雅实现高效率降维。
    
- 11. `chunk`
    
    - 面试痛点：如何把一个一维数组，按照指定的 size 分割成一组二维数组（经典应用：前端纯按页分组列表）？
    - 源码精髓：极其精准的指针步长控制，通过 `while (index < length)` 不断裁切。
    
- 12. `difference` (核心底层：`.internal/baseDifference`)
    
    - 面试痛点：求两个数组的差集。如果右边数组极大，怎么优化比对效率？
    - 源码精髓：内部将大数组转化为特殊的 `cache` 结构，将时间复杂度从 $O(n \times m)$ 降到近似 O(n)。

## 🗺️ 第三阶段：高级对象、路径导航与结构重组（13 ~ 18 题）

_核心目标：掌握深层对象导航。解决前端长期以来面临的“多层嵌套数据可能引发 `Cannot read property ... of undefined` 报错”的痛点。_

- 13. `get` (核心底层：`.internal/baseGet`)
    
    - 面试痛点：现场手写安全取值 `_get(obj, 'a.b[0].c', defaultValue)`。在可选链 `?.` 普及前这是绝对的霸主，现在依然是动态化配置的必考题。
    - 源码精髓：如何将各种奇怪的字符串路径（`.internal/castPath`）解析成标准的键名数组，并用 `while` 循环一层层剥开。
    
- 14. `has` (核心底层：`.internal/hasPath`)
    
    - 面试痛点：如何安全地判断一个深层路径是否存在（而不是只用 `obj.a !== undefined`，因为值可能就是 `undefined`）？
    - 源码精髓：完美结合了 `Object.prototype.hasOwnProperty` 与深层路径遍历。
    
- 15. `set` (核心底层：`.internal/baseSet`)
    
    - 面试痛点：如果要对一个深层对象赋值（如 `_set(obj, 'a.b.c', 1)`），如果中间的 `b` 节点不存在，如何自动帮我创建好空对象？
    - 源码精髓：在遍历路径时，动态判断下一层是否是数字（决定创建数组还是普通对象），非常考验工程逻辑。
    
- 16. `pick` 与 `pickBy`
    
    - 面试痛点：怎么从一个有 50 个字段的大对象里，只要我们指定的 3 个字段？
    - 源码精髓：学习其内部使用基础的键值对分配机制（`basePick`），只捞取并重组我们需要的子集。
    
- 17. `omit` 与 `omitBy`
    
    - 面试痛点：与 `pick` 相反，如何优雅地过滤并剔除掉指定的属性，生成一个新对象？
    - 源码精髓：理解它是如何先通过 `keys` 拿到全量键名，然后取其补集再调用 `pick` 逻辑的。
    
- 18. `keys` 与 `keysIn`
    
    - 面试痛点：`Object.keys` 和 `for...in` 的本质区别？如何拿到原型链上的可枚举属性？
    - 源码精髓：看 Lodash 是如何进行严密的跨浏览器兼容，并处理类数组（arguments）、字符串等特殊情况的键名提取。

## ⏳ 第四阶段：高级函数、闭包应用与异步控制（19 ~ 24 题）

_核心目标：攻克闭包与高阶函数。中高级前端面试的终极分水岭，大厂现场手写几率最高的一块。_

- 19. `once` (依赖 `.internal/before`)
    
    - 面试痛点：如何写一个高阶函数，让用户的某个核心操作（比如表单提交、支付按钮、初始化事件）不管点多少次都只执行一次？
    - 源码精髓：最经典的闭包应用，内部通过一个状态标识符拦截并返回第一次执行的缓存结果。
    
- 20. `memoize`
    
    - 面试痛点：什么是高阶函数的“记忆化（缓存）”？当遇到斐波那契数列等高频、重复的递归计算时，如何用一行代码做性能飞跃？
    - 源码精髓：闭包维持一个内部 `Map` 充当缓存容器，看它如何提供自定义 `resolver` 来弹性生成缓存键名。
    
- 21. `curry` (核心底层：`.internal/createWrap`)
    
    - 面试痛点：现场手写函数柯里化（Currying）。什么是函数的惰性求值和参数复用？
    - 源码精髓：非常高级的闭包和递归。核心在于对比“当前收集到的参数总个数”是否大于或等于“原函数所需的参数个数（`fn.length`）”。
    
- 22. `delay`
    
    - 面试痛点：比原生 `setTimeout` 更优雅的延迟执行器，如何让它在延迟的同时还能支持向目标函数注入参数？
    - 源码精髓：巧妙利用剩余参数（Rest Parameters）以及对经典定时器的封装。
    
- 23. `debounce` (防抖)
    
    - 面试痛点：前端面试的“镇店之宝”。请现场手写一个功能完整的防抖函数，必须包含：立即执行（`leading`）、最后一次执行（`trailing`）、以及中途取消（`cancel`）。
    - 源码精髓：整个源码库中最具含金量的单文件之一。通过精准比对“当前时间戳”与“上次执行时间戳”，结合定时器，把时间轴调度玩到了极致。
    
- 24. `throttle` (节流)
    
    - 面试痛点：现场手写节流函数。防抖和节流在底层逻辑上有什么共同点？
    - 源码精髓：震撼人心的是：Lodash 的 `throttle` 内部一行核心逻辑都没有，它完全是配置了 `{ maxWait: wait }` 的 `debounce` 变体！ 读懂这个会让你对防抖节流的底层认知瞬间通透。

## 🚀 第五阶段：终极挑战——算法深水区、递归与深度对比（25 ~ 30 题）

_核心目标：突破高级、资深架构师面试关卡。大厂终轮技术面试的“压轴题”。_

- 25. `assign` 与 `extend` (或 `assignIn`)
    
    - 面试痛点：`Object.assign` 是浅拷贝吗？它在拷贝时如果遇到了不可枚举属性或者原型链上的属性会怎么处理？
    - 源码精髓：精细化处理属性描述符和键名，通过循环将源对象的属性完美覆盖到目标对象。
    
- 26. `merge` (核心底层：`.internal/baseMerge`)
    
    - 面试痛点：`assign`（浅覆盖）和 `merge`（深合并）的区别是什么？如果两个对象的同一个属性都是对象，怎么把它们深度融合成一个，而不是直接覆盖？
    - 源码精髓：深度递归合并。它会深入到对象的骨髓里，把深层的属性树进行交叉合并。
    
- 27. `clone` (浅拷贝)
    
    - 面试痛点：JS 中怎么手写浅拷贝？遇到基础类型、数组、普通对象，各自的最佳克隆姿势是什么？
    - 源码精髓：大厂标准的浅层快速复制手法，干净利落。
    
- 28. `cloneDeep` (核心底层：`.internal/baseClone`)
    
    - 面试痛点：深拷贝的天花板实现。怎么处理大对象深拷贝时的循环引用死循环（Circular Reference）？怎么支持 `Map`、`Set`、`Date`、`RegExp`、`Symbol` 键名？
    - 源码精髓：引入 `Stack` 机制（现代版本使用 `WeakMap`）充当克隆备忘录。利用类似图的拓扑遍历，完美克隆整个内存网络。
    
- 29. `isEqual` (核心底层：`.internal/baseIsEqual`)
    
    - 面试痛点：现场手写深度比较（Deep Equal）。两个长得一模一样但引用不同的对象（例如 `const a = {x:1}; const b = {x:1};`），怎么让 `_isEqual(a, b)` 返回 `true`？
    - 源码精髓：这也是一个极其庞大的递归比较算法。它会逐层剥开对象的衣服，比较它们的构造函数、原型、键名长度，并同样用 `Stack` 机制死死卡住循环引用带来的死循环。
    
- 30. `template`
    
    - 面试痛点：如何手写一个微型字符串模板引擎？类似 Vue/React 的初级编译原理（将 `<%= name %>` 替换为真实数据）。
    - 源码精髓：利用正则表达式提取标识符，通过极其精妙的 `new Function(data, code)` 动态执行拼接出来的 JavaScript 代码字符串，这是前端高级编译/运行时的经典缩影。
